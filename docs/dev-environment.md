# Real AWS development environment

The default Spring profile is `local`. It uses LocalStack for S3, SQS, SNS, and Cognito emulation and never falls back to real AWS endpoints. The `dev` profile is an explicitly selected learning environment for real SQS, SNS, and Cognito in `us-east-1`; S3 remains on LocalStack.

## Credentials and safety

Use a dedicated non-root AWS identity and the named profile `rms-dev`, or copy `.env.dev.example` to the gitignored `.env.dev`. The application uses the AWS SDK default credential chain whenever `AWS_ENDPOINT` is blank, so credentials can come from `AWS_PROFILE`, environment variables, or the standard AWS config files. Never commit access keys.

Before provisioning resources, create the one-dollar billing budget/alarm and use the least-privilege policy generated by `scripts/aws/dev-env.sh`. Resource names use the `rms-dev-` prefix and all resources are co-located in `us-east-1`.

## Provisioning order

```bash
export AWS_PROFILE=rms-dev
export AWS_REGION=us-east-1
./scripts/aws/dev-env.sh provision
```

The script creates the standard event queue and DLQ, the SNS notifications topic and SQS subscription, and the Cognito user pool/app client. It is idempotent for named resources and prints values needed by the `dev` profile. Configure the printed values as environment variables before starting the app:

```bash
SPRING_PROFILES_ACTIVE=dev \
AWS_PROFILE=rms-dev \
AWS_REGION=us-east-1 \
AWS_PAYMENT_TOPIC_ARN=<topic-arn> \
AWS_RECONCILIATION_QUEUE_URL=<queue-url> \
COGNITO_ISSUER_URI=https://cognito-idp.us-east-1.amazonaws.com/<user-pool-id> \
./mvnw spring-boot:run
```

The rollout order is SQS, SNS, then Cognito. Run the bounded smoke checks after each stage:

```bash
./scripts/aws/smoke-test.sh
```

## Cognito API-only testing

The app client has no secret. Create test users with the AWS CLI or console, then use the Cognito `USER_PASSWORD_AUTH` flow to obtain an access token. Send that token as `Authorization: Bearer <token>` to protected `dev` endpoints. The `dev` security chain validates the Cognito issuer, signature, expiry, and audience; Cognito groups such as `USER` are mapped to `ROLE_USER`.

## Teardown

Inspect the resource inventory before deleting anything, then run:

```bash
./scripts/aws/dev-env.sh teardown
```

This only targets resources with the `rms-dev-` names and does not contact or delete LocalStack resources. The script never runs an unbounded poll or publish loop.

Cloudflare R2 is a possible future S3-compatible option if a public object store is needed; it is not part of this environment.
